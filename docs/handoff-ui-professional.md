# 专业协作工作台 UI 优化交接报告

日期：2026-10-17
设计方向：用户选定的第二套方案「专业协作工作台」

## 原来是什么样

- 浅色界面同时使用蓝紫、紫色和多组灰色，主色与语义色没有完全统一。
- 手机首页以大尺寸主 Bot 头像为视觉中心，更像角色展示页，工作台身份较弱。
- 宽屏导航、会话列表和聊天区已经可用，但标题、搜索框、会话行和按钮的尺寸偏大，信息密度不够稳定。
- 消息气泡在手机和宽屏使用两套差异较大的视觉语言；宽屏用户消息为高饱和紫色，和其余工作台界面不协调。
- 团队页按整个窗口宽度决定列数，没有扣除宽屏侧栏；折叠屏右侧实际空间不足时仍可能排三列。
- PC 没有独立上下文区域，团队状态、队列和最近活动都混在聊天时间线附近。
- 页面切换时 ArkUI 可能复用 Scroll 偏移，设置页有从中间位置打开的风险。

## 做了什么

### 1. 建立统一的企业级视觉令牌

`view/Theme.ets` 统一为：

- 瓷白页面底色 `#F5F7FA`；
- 深海军蓝正文 `#172033`；
- 钴蓝品牌色 `#3F5EF5`；
- 更克制的分隔线、成功、警示、危险与代码块颜色；
- 深色模式同步调整为蓝灰工作台体系。

`Index.ets` 的页面底色、面板、文字与分隔线改为直接读取 `ThemeTokens`，减少父组件和子组件的色值漂移。

### 2. 手机端：从角色展示页改为工作台首页

`view/MobileHome.ets`：

- 顶栏加入蓝鲸品牌、`DS Bot` 与「智能协作工作台」副标题；
- 搜索、新建、设置改为统一的 40vp 方圆按钮；
- 100vp 大头像改成紧凑的「主 Bot」工作卡，展示在线状态并保留单击/长按行为；
- 会话列表增加「最近会话」层级，行高、字号、间距和分隔线统一；
- 原有搜索、创建 Bot、设置、打开主会话和诊断入口保持不变。

### 3. 折叠屏与平板：重做侧栏层级和列表密度

`view/DesktopSidebar.ets`：

- 导航栏使用页面浅灰底，内容列继续使用白色，形成清晰的三层工作区；
- 品牌区、导航按钮、刷新按钮、搜索框和连接状态采用统一方圆半径；
- 会话标题增加数量说明，隐藏会话开关与「最近会话」标题合并；
- 会话行缩短并增加选中态左侧钴蓝指示条；
- 摘要补省略处理，保留置顶、隐藏与等待状态。

### 4. 聊天区：统一消息与输入体验

- `MessageBubble.ets`：用户消息统一为浅蓝底深色文字，Bot 消息为白色描边面板；手机和宽屏共享同一视觉语言。
- 气泡圆角由大胶囊收敛为 14/18vp，行间留白更紧凑。
- `ChatComposer.ets`：输入框、附件与发送按钮统一为 12/14vp 方圆控件，不再混用大胶囊和文字按钮。
- 聊天顶栏按钮、停止/置顶/隐藏动作统一为工作台式小圆角按钮。
- 宽度算法继续从唯一的聊天内容宽度推导；PC 上会额外扣除上下文栏，避免气泡越界。

### 5. 团队与设置页

- `TeamPage.ets` 的 Bot 卡片改为「头像 + 名称/角色/状态 + 进入箭头」信息行。
- 列数改为按实际内容区宽度计算：折叠屏窄内容区为一列，足够宽时才扩到两/三列。
- 创建 Bot、创建群聊的输入框、标签与按钮统一到钴蓝工作台样式。
- `SettingsPage.ets` 使用品牌图标、白色分组面板、细描边和 14vp 圆角。
- 桌面设置页使用独立 `Scroller`，进入页面后主动回到顶部，避免复用上一页面偏移。
- 配对页、创建 Bot 页、审批卡同步使用相同主色、圆角和描边体系。

### 6. PC 专属上下文栏

新增 `view/WorkspaceInspector.ets`，在 `>=1200vp` 的聊天工作区右侧显示：

- 当前会话与就绪/进行中状态；
- 团队成员及工作状态；
- 当前任务、排队数量；
- 最近四条真实会话活动。

上下文栏只消费父组件投影后的视图数据，不读取协议对象、不发起网络请求；点击 Bot 复用团队页已有的会话打开行为。

## 现在是什么样

- 手机、折叠屏、平板和 PC 共用一套品牌色、语义色、圆角、分隔线和文字层级。
- 手机突出「开始协作」和最近会话，不再把大头像当成页面主体。
- 折叠屏是明确的「导航栏 / 会话列表 / 工作区」结构，内容更紧凑。
- 团队页在折叠屏实际右侧宽度下自动使用单列，Bot 名称、角色和状态完整可见。
- PC 在空间足够时形成「导航 / 会话 / 聊天 / 上下文」四层工作区；折叠屏和平板不会强行显示右栏。
- 设置页切换后稳定从顶部显示。

## 2026-10-17：顶部与底部留白修复

### 原来什么样

- 页面只覆盖系统安全区，状态栏和底部手势区继续使用系统默认白色背景；
- 在浅色主题的 `#F5F7FA` 页面上下形成两条色差明显的白带；
- 切换深色主题时，系统栏也不会随主题更新。

### 做了什么

- `EntryAbility.ets` 在主窗口创建时使用鸿蒙原生 `setWindowSystemBarProperties`，统一状态栏、导航栏背景与图标颜色；
- `Index.ets` 增加只负责绘制背景的安全区图层，并用 `expandSafeArea` 延伸到顶部状态栏和底部手势区；
- 实际页面内容不扩展，仍由系统安全区避让，避免标题、按钮、输入框与状态栏/手势条重叠；
- 深色模式统一经 `toggleDark()` 切换，并同步更新两处系统栏的背景与图标明暗。

### 现在什么样

- 手机、折叠屏的页面背景从顶部状态栏连续延伸到底部手势区，不再出现独立白带；
- 系统时间、电量、网络与底部手势条仍正常可见和可操作；
- 浅色、深色主题都使用匹配的系统栏颜色，页面内容布局没有上移或下沉。

### 验证

- ArkTS 类型检查及 HAP 构建：`BUILD SUCCESSFUL`；
- 纯逻辑测试：103 passed / 0 failed；
- 手机模拟器：`1320×2856`，布局 dump 中内容安全区为 `y=137..2758`，背景安全区图层为 `y=137..2856`；
- 折叠屏模拟器：`2210×2416`，覆盖安装与页面启动成功；

## 2026-10-17：聊天输入栏比例调整

### 原来什么样

- 手机聊天页同时存在外层和 `ChatComposer` 内层的左右 20vp padding，输入区被重复压缩；
- 附件按钮和图标发送按钮均为 42vp，宽屏文字发送按钮为 68vp，和有效输入宽度相比显得过重；
- 两侧按钮间距为 8vp，进一步减少了文本输入区域。

### 做了什么

- 删除手机聊天页对 `ChatComposer` 的重复外层 padding，只保留组件内部统一边距；
- 手机两侧按钮从 42vp 收敛到 38vp，图标从 24/22vp 收敛到 18vp；
- 宽屏附件按钮调整为 36vp，文字发送按钮从 68vp 调整为 56vp；
- 按钮间距由 8vp 调整为 6vp，圆角统一为 10vp。

### 现在什么样

- 文本输入框获得更多横向空间，手机上的长提示文字和输入内容更不容易过早换行；
- `+` 与发送按钮保持清晰可辨，但不再抢占输入框的视觉重心；
- 手机、折叠屏与宽屏继续共用同一个 `ChatComposer`，没有新增重复实现。

## 2026-10-17 复核：PC 端实测与一处宽度回归修复

本节是对上文「后续注意事项」中 **PC 上下文栏未在真实设备验证** 的补充。
本轮启动了 `MateBook Pro` 2in1 模拟器（此前没有 PC 模拟器），完成实测并**发现一处真实回归**。

### 发现的问题：PC 上工具卡撑破气泡（越出 38px）

第一次在 PC 上看到工具卡尾部被裁切（`list_bots  10 ms  完…`）。布局 dump 精确量到：

```
气泡内容列 Column  右边界 2434
工具卡 Column      右边界 2472   → 越出 38px（全屏共 16 个节点越出）
```

**根因**：`chatPaneWidth()` 用 `this.sideBarWidth` **状态值**推算聊天区宽度：

```ts
return this.windowWidth - this.sideBarWidth - inspector;
```

但侧栏宽度由原生 `SideBarContainer` 管理，**用户拖拽分隔条后 `sideBarWidth` 状态不会同步**，
于是推算出的聊天区比实际宽，气泡与工具卡按偏大的宽度排版 → 越出内容区。

**修法：算不如量**。改为测量实际宽度：

- 聊天列外层挂 `onAreaChange`，把真实宽度写入 `@State chatPaneMeasuredWidth`；
- `chatPaneWidth()` **优先返回测量值**，测不到时才回退到推算；
- 宽屏（含上下文栏）与窄屏两个分支都挂了测量。

### 修复后验收

| 场景 | 窗口宽 | 上下文栏 | 越出 |
|---|---|---|---|
| PC 窗口模式 | 2090px（≈1045vp） | 按设计隐藏（<1200vp） | 0 |
| **PC 最大化** | 3120px（≈1560vp） | **显示** | **0** |
| 折叠屏（706vp） | 2210px | 不显示 | 0（10 屏 / 1520 节点全量扫描） |

- 工具卡 `已完成` 完整可见，不再裁切；
- PC 四栏结构正常：导航栏 / 会话列表 / 聊天区 / 任务与活动；
- 上下文栏内容正确：`团队成员`（Chief、Searcher，均「可用」+ 绿点）、
  `当前任务`（等待新的协作请求）、`最近活动`（4 条真实事件）。

证据：`docs/qa/p1/device-pc-maximized.jpeg`、`device-pc-workspace-fixed.jpeg`。

### 给后续开发者的提醒

**涉及宽度的计算不要依赖「窗口宽 − 侧栏宽」这类推算**——侧栏由原生
`SideBarContainer` 管理且可拖拽，状态值会滞后于实际布局。
优先用 `onAreaChange` 测量真实宽度（本工程已在聊天列落地）。
这条规则同样适用于本次新增的 `WorkspaceInspector` 等固定宽度侧栏组合。
